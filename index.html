User interfaces are broken.

Pax is an open source project on a mission to fix them.

What's broken, exactly?

The way the world creates apps & websites is complicated, inaccessible, and anti-artistic:

Too complicated

  • Sprawling landscape
  • Unintuitive layout systems, complicated legacy standards, responsiveness
  • Toolchains and collaboration flows

Not accessible to enough of humanity

  • Too technical
  • Need WYSIWYG
  • Needs to empower collaboration with AI

Should empower artist expression

  • Very few people can create because you must be technical. Visual artists shouldn't need to be highly technical.
  • Creative tooling should be part of the spec
  • APIs designed for design & creativity — simplicity, modern foundation instead of legacy, animations, with room to expand into game engine-like
  • No-code is not the answer — cutting off code cuts off control & ownership, and limits art

And how does Pax seek to fix these problems?

Designed for visual & AI creation

Uniquely, Pax enables creating user interfaces visually and with AI tools, hand-in-hand with writing code.

Reduce complication

  • Build once, deploy to any device — because Pax is built at a very low level — the same level as operating systems and web browsers — Pax targets web browsers (via WASM) and operating systems with native conventions, GPU rendering, and unmatched performance.
  • Simplified, intuitive layout systems
  • Hermetic separation between markup language & application code — keeps UI definitions clean & simple, with compiler-level enforcement

Design for all of humanity

  • 100% free & open source
  • Visual & AI tooling, with complete code control
  • a11y out of the box

Empower art

  • Creative tooling for artists, empower the creative human spirit
  • "With code" Pax's philosophy is "with code" — inviting non-coders to contribute to the same codebases as developers, using code as a system of record, through visual & AI creative tools.

How does it work?

Pax enables describing "anything you might build with React or SwiftUI" and "anything you might design in Photoshop or Figma".

By building both a classic UI development tool and a visual creative tool around the same foundation, Pax unlocks a fundamentally better way to create user interfaces: collaboratively, across developers, designers, artists, and AI — using a codebase as the system of record.

Pax is initially focused on today's professionals, while laying the infrastructure for the billions of creators around the corner.

A bit more technically:

The crux of Pax's invention is a declarative user interface description language — union of a markup language (like HTML) and an expression language (like Excel). These user interface definitions attach to a programming language — allowing Turing-complete application logic while keeping user interface definitions 100% declarative, enforced at the language and compiler level.

[Separation of concerns with application code — diagram]

Further, Pax is designed to render in "design tool space" — the same intuitive coordinate system used by tools like Powerpoint or Google Slides, as well as professional creative tools like Photoshop and Figma.

To execute this invention, we needed to build:

  • Parser & compiler
  • Rendering engine, GPU rendering, prioritizing portability, performance, and resource efficiency
  • Platform-specific runtimes, native compositing
  • Programming language integrations: Rust [reflection, compiletime integration, runtime integration], TypeScript is planned
  • Layout engine, top-down, responsive by default
  • Build tooling: package into wasm apps or native apps (macOS and iOS alpha)
  • Pax Designer: a vector design tool that reads & writes code
  • Pax Visual AI: ICL prompt that teaches Pax and enables visual AI collaboration

How can I try it out?

Today, building with Pax requires familiarity with the Rust programming language. If you're comfortable with Rust and a terminal, get started here.

In the near future, we plan to expand Pax's programming language support to include TypeScript, and possibly other languages like Python, Swift, C++, and Go.

Check out the docs for instructions on getting started.
Also check out the GitHub repo to run examples or contribute to the project.
